# 2.8.3 — подготовка LOD независимо от экспорта

31 октября 2026, Fabric 1.21.11 / Java 21. Voxy 0.2.16-beta, VoxyWorldGen 2.2.4.

## Живые наблюдения на 2.8.2

mcpfabric подключён. После просьбы оставить игрока на месте были сняты
`td-stats`, снимок экрана и стеки потоков. Нейросеть и поток экспорта работали;
постоянного общего зависания не обнаружено. Первый короткий интервал около
49 секунд не дал новых raw-тайлов: оставалось 296. За общий интервал 351.984 с
счётчик вырос 296 → 352, промежуточных окон 508 → 605, рассчитанных водных
ядер 29 → 40. Счётчик отдельных prefetch-стадий оставался 0; дальняя подготовка
шла другим путём через LOD. Это около 9.5 новых raw-тайлов в минуту в данном
отрезке. Такой темп не является универсальным бенчмарком.

Средняя inference-задача в общем счётчике занимала около 0.75–0.78 с,
максимальная — 5.36 с; эта задача включает пайплайн, не только один ONNX Run.
Снимок статуса показывал около 1400 незавершённых колонок, лишь одну из них
с ожиданием леса; сам экспорт шёл. Логи содержали повторные пики давления
кадрового бюджета. Нулевой prefetch не доказывает самостоятельную причину:
ближние цели могли быть уже подготовлены реальными чанками.

## Исправления

1. Работник подготовки получил собственный ленивый обход водных ядер.
   Когда очередь срочных запросов экспорта пуста, он ищет ближайшее отсутствующее
   ядро внутри запрошенного радиуса. Подготовка теперь может идти до того,
   как экспорт пройдёт все уже готовые поверхностные колонки. Обход не загружает
   реальные чанки и не содержит полного списка координат в памяти.
2. Если перед дальним запросом отсутствует ближайшая цель prefetch, контроллер
   выполняет один допустимый шаг этой ближайшей цели. Ранее дальний работник
   просто ждал, пока её подготовит другой производитель. Общая блокировка
   и допуск по бюджету сохранены.
3. Повторяющиеся пики могли удерживать pressure=4 без секунды спокойствия,
   из-за чего условие pressure<3 навсегда запрещало фон. Теперь после окна
   немедленной паузы допускается редкий общий шаг: при pressure=4 не чаще
   одного раза в 1.25 секунды. Свежий пик, устаревшие кадры, пауза, отсутствие
   активного измерения и постоянно медленный рендер по-прежнему ограничивают
   запуск; реальные чанки сохраняют приоритет.
4. `/td-stats` дополнен снимком состояния клиентского моста, разрешениями
   `publish` / `prepare` и статистикой кадров. Снимок создаётся на клиентском
   тике раз в секунду; серверная команда читает готовую строку, не обращаясь
   к изменяемой клиентской очереди из другого потока.

Сохранены предел 32768 блоков, команда `/td-voxy start 32768`, ранняя очистка
старого высокого LOD, маски настоящих чанков, водный алгоритм 4 и геометрия.
Конфиги, установленный JAR, мир и кеш Voxy при разработке не заменялись.

## Проверки и практический предел

`gradlew build`: 199 тестов без ошибок и пропусков. Новые регрессии проверяют
самостоятельный выбор ядер без запросов экспортёра, отрицательные координаты,
смену позиции, пропуск готовых ядер и прекращение повторного опроса, а также
редкий общий допуск при постоянных кратких кадровых пиках. Проверен приоритет
ближней цели при подготовке дальнего запроса.

Новая сборка в игру ещё не установлена: измеренного ускорения 2.8.3 пока нет.
Для сравнения: тот же мир, позиция и настройки, активная игра без движения;
два `/td-stats` с интервалом 60 секунд. Сравнить raw-тайлы, водные ядра,
число записанных порций и `publish`/`prepare`. Не сравнивать только FPS.

2048 чанков — радиус 32768 блоков. Мост по-прежнему рассчитывает для него
полные карты высот и водные планы, а не отдельный грубый нейросетевой обзор.
Площадь такого круга в 256 раз больше прежнего радиуса 128 чанков. Новая
очередь уменьшает простои, но не обещает быструю готовность всего горизонта.
Для существенного ускорения полного дальнего вида нужен отдельный уровень
грубого предпросмотра с согласованием с точными данными; это ещё не реализовано.
