# GPU-сессии — 2.9.1, 31 октября 2026

Устранено повторное создание ONNX-сессий при переключении coarse/base/decoder.
При `inference.offload_models=true` теперь работает ленивый LRU-кэш до трёх
сессий. Численные параметры моделей и порядок вычислений не менялись.

## Причина изменения

В живом профиле 2.9.0 base и decoder создавали сессии по 60 раз. Среднее время
создания составляло примерно 1253 и 426 мс соответственно: суммарно около
101 секунды только на создание. Это накопленное время работы, не длительность
одного кадра. Старый единственный GPU-слот выгружал предыдущую модель при
каждом переключении. Буферы входа этой причины не устраняли.

## Поведение

- По умолчанию `inference.gpu_session_cache=3`. Старый пользовательский файл
  без нового ключа получает это значение автоматически. Существующее
  `inference.offload_models=false` сохраняет прежний режим резидентных моделей.
- Значение 1 возвращает прежнюю экономию памяти; 2 оставляет два последних
  сеанса. Изменения настройки требуют перезапуска. CoreML использует один слот.
- При распознанной ошибке памяти DirectML (`8007000E`) или CUDA текущие
  кэшированные сессии освобождаются, выполняется одна повторная попытка с
  одной сессией. Этот предел сохраняется до освобождения кэша моделей.
  Ошибки формы входа и другие ошибки вычислений не получают скрытого повтора.
- Кэш удерживает общий замок на время native Run. Активную сессию нельзя
  выгрузить посреди вызова. Сам native Run не прерывается и не распараллеливается.
- `/td-stats` содержит `gpuCache`: resident/hits/created/evicted/memoryFallbacks/
  memoryLimited. Чтение статистики не ждёт GPU-замка на серверном потоке.
  Время закрытия теперь относится к действительно закрываемой модели.

Удержание сессий увеличивает расход VRAM. Это предел числа сессий, а не бюджет
байтов; резервирование драйвера и промежуточные тензоры также используют память.
Повтор при OOM не предотвращает подкачку VRAM драйвером. На машине пользователя
read-only `nvidia-smi` показал RTX 5060, 8151 MiB всего и 2972 MiB свободно
во время проверки; этого измерения недостаточно для гарантии пикового бюджета.

## Проверка

216 тестов, без ошибок и пропусков. Восемь новых проверок включают:

- 60 последовательностей coarse/base/decoder: 3 создания вместо 180 при
  односессионной политике, 177 повторных использований; каждое закрытие ровно раз.
- LRU, уменьшение лимита, ошибки загрузки и Run, ровно один повтор при OOM,
  сохранение исходной ошибки при неуспехе повтора.
- Закрытие во время активной задачи ждёт её завершения, статистика не ждёт.
- 36 настоящих CPU-вызовов ONNX Identity через три кэшированные сессии:
  значения совпали побитово, включая -0. Это тест жизненного цикла и результатов,
  не измерение скорости terrain-моделей на DirectML.

Новая сборка ещё не установлена в игровой профиль. FPS и скорость заполнения
2048 чанков этой версией не измерены. Для проверки после замены JAR сравнить два
`/td-stats` в активной игре: после первого использования каждой модели
`sessionCreate` не должен расти на каждом переключении, а `gpuCache.hits` растёт.
Если был OOM, вывод явно покажет `memoryLimited=true`.

## Грубый дальний LOD: результат исследования

Текущий bridge продолжает отправлять точный предпросмотр; грубый LOD в 2.9.1
не включён. Увеличение радиуса само по себе не заменяет его.

В опубликованном исходнике Voxy 0.2.16-beta `WorldUpdater.insertUpdate` начинает
с уровня 0, пишет 16³ элементов и распространяет мипы вверх до уровня 4.
Нынешний адаптер вызывает именно этот путь. Поэтому разреженная карта высот,
переданная через существующий encoder, всё равно потребует мелких секций.

Подтверждено по коду и установленному model config:

1. `WorldPipeline.getCoarseSlice()` требует только coarse-стадию. В ней 20
   шагов, окно 64×64 с шагом 48, шесть взвешенных каналов и канал весов.
2. Один coarse-пиксель соответствует `32 * latentCompression * worldScale`
   блокам: при latentCompression=8 и масштабе мира 2 это 512 блоков.
   Климат/высоту надо нормировать по весам; высота использует преобразование
   со знаком и квадратом. Это низкочастотное условие модели, а не точная
   финальная высота с decoder, горной поправкой и руслами.
3. Радиус 32768 блоков означает порядка 3.29 млн горизонтальных ячеек 32×32,
   ещё без вертикальных секций. На сетке 512×512 это порядка 12.9 тыс. ячеек.
   Это оценка объёма сетки, не обещание ускорения в 256 раз.
4. В Voxy есть публичные низкоуровневые методы доступа к WorldSection, но
   корректный писатель крупных уровней обязан обновлять состояние детей,
   соседей, грязных секций и предков. Простая запись в raw array этого не делает.
5. Защита реальных чанков сейчас действует отдельно по 16×16. Крупная запись
   уровня 4 охватывает 512×512 и может задеть мипы реальных чанков. Нужны
   отдельное владение preview, запрет перезаписи точных детей, очистка старого
   coarse-рельефа и проверка гонки с обычным ingest при приближении.

Следующая реализация — отдельный coarse-писатель Voxy и очередь уточнения,
сначала с тестом шва на копии мира. Нельзя считать высоты coarse готовыми
raw-тайлами или сохранять их в точный TerrainRepository/водные планы: иначе
приближение игрока может использовать предварительный рельеф как окончательный.
Эти необходимые изменения не скрыты под переключателем уже готовой функции.
