# 2.6.0 — непрерывный LOD, VoxyWorldGen и морские устья

Целевая связка: Minecraft 1.21.11, Fabric, Voxy 0.2.16-beta. Дополнительно
поддерживается **VoxyWorldGen 2.2.4**. Чужие JAR/классы/исходники не включены.
Дополнительный скилл для этой работы не потребовался.

## Передача данных и микрофризы

- Фоновая подготовка LOD теперь включена автоматически, отдельный `start`
  для начала больше не нужен. Радиус по умолчанию 1024 блока. Передаются и уже
  готовые данные, и постепенно подготавливается недостающая территория.
- Передача разбита на порции: за шаг записывается максимум одна секция 32³.
  Столбец продолжается с сохранённой позиции, без повторного sampling. До восьми
  уже существующих секций можно быстро пропустить за один шаг без записи.
- Между шагами выдерживается 8/16/50 ms по среднему времени кадра. Клиентский
  поток только закрепляет engine и проверяет реальные чанки; заполнение,
  уменьшение детализации и запись выполняет worker. Очередь содержит одну цель.
- Измеряется промежуток между кадрами и CPU-время render. После заметного
  скачка новые передачи/тяжёлые шаги получают паузу 250 ms. Устойчиво медленный
  рендер сохраняет небольшие передачи готового LOD, но откладывает inference.
  Это программный сигнал, а не точное время GPU kernel.
- Для подготовки рельефа/воды есть общий для производителей допуск: максимум
  один новый фоновый шаг каждые 250 ms при здоровом кадре. Приоритет имеют
  недостающие участки впереди игрока; дальняя радиальная очередь Voxy не
  отбирает у них бюджет. Срочная генерация чанков не требует этого допуска.
- Уже запущенный ONNX-вызов или mip/запись одной секции не прерывается.
  Поэтому обещать полное отсутствие микрофризов до игрового профиля нельзя.

Из горячего пути убраны повторные копии массивов готового рельефа. Экспорт
возвращает один неизменяемый view на уже замороженный tile. Во внешний API
массивы не раскрываются. Публичные конструкторы по-прежнему копируют входы.
Сэмплер обходит исходные tiles блоками, вместо создания ключа/хеша на каждую
колонку. Свежие массивы результата передаются внутреннему immutable объекту
без второй копии. Палитры и voxel buffer переиспользуются в пределах engine,
при смене мира освобождается ссылка кэша. Кодировщик имеет общий lock для
завершающейся старой и новой сессии, не затрагивая главный генератор Minecraft.

## VoxyWorldGen 2.2.4: режим координации

У этой версии нет общего публичного provider API для нашего генератора.
Здесь реализован **согласованный режим**, а не подмена её noise-generator:

- В обычном измерении Terrain Diffusion тяжёлый фоновый FULL-chunk генератор
  VoxyWorldGen приостанавливается через его pause API и небольшой optional
  Mixin. Вместо него работает наш прямой поток высот/биомов/воды в Voxy.
- Из публичных настроек VoxyWorldGen берутся enabled и generationRadius.
  Радиус переводится из чанков в блоки и ограничивается 64..2048. Команда
  `/td-voxy start <blocks>` может явно выбрать другой радиус.
- Исходный callback паузы сохраняется. После initialize он привязывается снова,
  поскольку VoxyWorldGen при инициализации сбрасывает проверку паузы.
- В одиночной интегрированной игре дополнительно пропускается дублирующая
  сериализация настоящего чанка в сетевую отправку VoxyWorldGen: Voxy уже
  получает его от локального клиента. При других игроках LAN этот перехват
  не используется. Реальные чанки всегда имеют приоритет перед прогнозом.
- Обычные миры, Nether/End и серверная установка без нашего клиента сохраняют
  штатный генератор VoxyWorldGen. Это не новый протокол серверных LOD для
  удалённых клиентов. Встроенная статистика FULL-генератора не считает наши
  виртуальные секции; их прогресс находится в `/td-voxy status`.
- Optional Mixins загружаются только для mod ID `voxyworldgenv2`, версии 2.2.4.
  При иной версии или выключенной координации наш поток не запускается рядом
  со сторонним генератором. Без VoxyWorldGen прямой мост работает самостоятельно.

Voxy SeedGen одновременно по-прежнему не поддерживается. Другие импортёры
или фоновые генераторы нельзя считать согласованными с этим режимом.
Существующие секции Voxy пропускаются, старые ошибочные LOD не очищаются.

## Реки, озёра и море

Новая ревизия планирования применяется **только к отсутствующим планам**:

- Один стабильный hash-бакет из десяти исключает целое озеро вместе с его
  притоками либо систему, определённую морским выходом. Это примерно 10% по
  числу водосборов на большой выборке, не 10% площади воды в каждом квадрате.
  Уже сохранённые водоёмы не прореживаются, отдельные мокрые пиксели не удаляются.
- Сток доходит до настоящей морской колонки (first-air <=62), вместо прежней
  остановки на сухом пляже высоты 64. Это позволяет пройти и широкий пляж.
- На низком берегу короткий выход соединяется с уровнем воды моря Y=62,
  без обратного подъёма уровня. Высокий новый утёс ради устья не прорезается.
- Естественная подводная колонка за выходом не поднимается алгоритмом берега
  в удерживающую стенку. Подводная облицовка также не закрывает этот выход.
  Размещение воды допускает соприкосновение с существующей морской водой;
  этот допуск не применяется к лаве.

Сохранённые файлы и чанки не изменяются. Новая территория использует соседние
старые immutable водосборы вместе с новыми. Старые файлы v1 читаются; новые
файлы v2 хранят ревизию и допускают морской уровень 62. Имя каталога
`terrain-data/world-water-v1` оставлено прежним для чтения принятого мира.
**Сборки 2.5 и старше новые файлы v2 не читают**; для возврата к ним нужна
копия сохранения до открытия в 2.6. Существующие бугры/устья в старых чанках
автоматически не перестраиваются. Для наглядной проверки — новый тестовый мир
или область, планы которой ещё не рассчитывались.

Поверхность/свет LOD остаются упрощёнными. Деревья, структуры, пещеры, мелкие
полублоки и растительность появляются при штатном импорте настоящих чанков.
Прибрежная маршрутизация также исправляет ложные старые выходы, поэтому
изменение отдельных прибрежных участков не сводится только к 10% отбору.

## Команды и настройки

    /td-voxy status
    /td-voxy start 1024
    /td-voxy stop
    /td-stats

`status` дополнительно показывает frameGap/renderCpu и время передачи секции.
Среднее/максимум считаются за накопленный период, p95recent — по последним
256 событиям. Это позволяет сравнивать повторный полёт и новую территорию.

В `config/terrain-diffusion-mc.properties` после перезапуска:

    compat.voxy.enabled=true
    compat.voxy.prepare_ahead=true
    compat.voxy.radius_blocks=1024
    compat.voxy_worldgen.enabled=true

`/td-voxy stop` останавливает наш поток, принятые данные остаются. При включённой
координации native FULL-генератор в TD-мире продолжает быть приостановлен.
Отключение compat.voxy_worldgen при установленном VoxyWorldGen возвращает ему
штатное поведение и запрещает наш параллельный поток, чтобы не было двух писателей.

## Подтверждённые проверки и границы результата

Набор JUnit проверяет маленькие шаги и продолжение после паузы, оси/воду/свет
кодировщика и повторное использование буфера, отрицательные координаты и четыре
raw tiles в одной LOD-колонке, общий допуск/приоритет, отказ при смене сессии,
неизменяемость и повторный view, целое прореживание и статистику 20000 координат,
выход через узкий/широкий пляж и отсутствие морской стены, запрет прорезания
высокого утёса, различие воды/лавы, чтение v1/v2 и сохранение всех старых файлов.
Прежние тесты рек/водопадов/деревьев также сохранены.

Отдельный стенд сравнил 2.5.0 и 2.6 на 800 горячих экспортов через восемь
синтетических плоских замороженных ядер (кэш sampler держит четыре). Три пары
новых JVM с чередованием порядка: медиана **526.05 → 43.11 ms**, выделения
потока **1,773,173,720 → 8,469,872 bytes** (примерно на 99.5% меньше).
Контрольные значения совпали. Этот сценарий специально затрагивает повторный
экспорт при вытеснении view из sampler-кэша; цифры нельзя переносить на общий
FPS или общее потребление RAM. В стенде нет inference, игры, GPU и native Voxy.
Точные условия: локальный `recovery-evidence/streaming-v2/export-comparison.json`.

Публичный ABI официальных Voxy 0.2.16-beta и VoxyWorldGen 2.2.4 проверяется
отдельно, как и remap callback-ов/упаковка Mixins. Полный запуск этой новой
связки, фактический Mixin apply в игровом Fabric, GPU кадры и гонка настоящего
ingest в игре ещё требуют игрового прогона; тестовый sink это не заменяет.

Исходники внешнего проекта изучены по [официальному репозиторию](https://github.com/iSeeEthan/voxy_worldgen_v2).
Его [лицензия](https://github.com/iSeeEthan/voxy_worldgen_v2/blob/main/LICENSE)
не делает код свободным для копирования в наш проект. Новые адаптеры написаны
отдельно; внешние классы, исходники и JAR не входят в релиз. Реверс SeedGen
и дополнительные скачиваемые скиллы не использовались.
