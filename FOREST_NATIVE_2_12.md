# Лес, запуск Voxy и реальные чанки — 2.12.0

**Обновление 2.12.1:** команда `/td-voxy chunky` теперь принимает радиус в
чанках (1–2048). Например, `1024` = 1024 чанка = 16384 блока. Описание единиц
ниже относится к первоначальной 2.12.0; её пример `512` блоков теперь задаётся
командой `/td-voxy chunky 32`.

Исправления для Minecraft 1.21.11 / Fabric, 1 ноября 2026.

## Смена источника дальнего рельефа

По умолчанию `compat.voxy.source=chunks`: реальные чанки создаёт обычная
генерация Minecraft, в том числе запущенная через Chunky; Voxy использует
свой native ingest. Нейросетевой coarse-горизонт TD выведен из работы:
три экспериментальных render mixin не применяются, coarse-controller не
создаётся. Старый `compat.voxy.coarse=true` не может включить его обратно.
В этом режиме TD также не запускает собственный подробный LOD-exporter.

`/td-voxy start <блоки>` сообщает об источнике реальных чанков и не начинает
предгенерацию автоматически. Отдельный явный запуск:

```
/td-voxy chunky 512
/chunky progress
/chunky pause
```

Радиус задаётся в **блоках**, центр — положение игрока, форма — круг,
порядок Chunky — concentric. Команда доступна хозяину встроенного TD-overworld.
Существующая задача не заменяется, не отменяется и не перенастраивается.
Сначала разумно проверить небольшой радиус: 32768 блоков охватывает миллионы
полноценных чанков и существенно отличается по стоимости от прежнего LOD.
Эта сборка сама предгенерацию в пользовательском мире не запускала.

Адаптер использует публичный Chunky API v0: `ChunkyProvider.get().getApi()`,
`isRunning`, `startTask`. Контракт проверен по установленному **Chunky 1.4.55**
и [официальному API](https://github.com/pop4959/Chunky/wiki/Developer-API).
Свой планировщик чанков и низкоуровневый патч C2ME не добавляются.
В профиле установлен C2ME **0.4.0-alpha.0.28+1.21.11**; реальные чанки идут
через стандартный конвейер генератора. Совместный нагрузочный прогон новой
сборки с Chunky/C2ME ещё не выполнен.

Координация с VoxyWorldGen 2.2.4 сохраняется: его дублирующая предгенерация
в TD-overworld приостановлена, но подавление обычных chunk-broadcast в native
режиме отключено. Остальные измерения не меняются.

Дополнительный прежний экспорт доступен через источник `prepared` в меню.
Он ограничен полем подробного радиуса (256–8192 блока) и не создаёт coarse.
Настройки его фоновой подготовки и радиуса не управляют нативным Chunky/Voxy.
Уже сохранённый старый LOD в хранилище Voxy этой сборкой не стирается:
точные данные приходят при загрузке/импорте реальных чанков средствами Voxy.

## Лес без клеток

В TreeCandidates была общая полоса случайного выбора породы для каждого
квадрата 96×96 блоков. Поэтому соседние квадраты получали резко разный состав.
Возраст также выбирался по жёсткой сетке участков.

Теперь каждое дерево имеет независимый детерминированный выбор породы;
его вероятности изменяются плавно в мировых координатах. Поля масштаба
256 и 96 блоков дают дубовые/берёзовые/хвойные акценты со смешанными переходами,
сохраняя климатическую пригодность. Возраст тоже смешивается без жёстких клеток.
Реальные деревья и дополнительный LOD используют один ForestComposition.
Выбор не зависит от порядка подготовки чанков; отрицательные координаты
обрабатываются теми же непрерывными полями.

Изменения касаются **новых деревьев в новых чанках**. Сохранённый лес не
переписывается. Уже нарисованные карты/minimap тоже не переделываются сами.
Высоты, вода и биомы TerrainTile остаются прежними, формат мира не меняется.

## Берёза и зум

В подробном LOD использовались упрощённая эллипсоидная крона и другой профиль
ствола. При приближении картинки зумом отличие от настоящего дерева становилось
видно. Теперь дополнительный предпросмотр берёт те же voxel-формы ветвей,
ствола и листьев, что TreeShapeGenerator. Проверен полный набор блоков
изолированной берёзы, включая отрицательные/составные границы предпросмотра.
В основном native-режиме Voxy получает настоящие деревья из реальных чанков.
При этом собственное прореживание Voxy на дальних уровнях остаётся его
обычным поведением; отдельный живой тест зума/Photon этой сборкой ещё нужен.

## Сохранение настроек Voxy

Конструктор Voxy016Api раньше выполнялся в client initializer TD и загружал
VoxyConfig до готовности Voxy GPU factory. В Voxy 0.2.16 это приводит к
выключенному объекту конфигурации вместо чтения сохранённого файла.
Теперь сначала проверяется VoxyCommon.isAvailable, и только после готовности
на клиентском тике создаётся API. Проверка готовности сама VoxyConfig не трогает.
Окно настроек использует ту же защиту. В пользовательский voxy-config.json
мод не записывает принудительные enabled/дальность; намеренное выключение
Voxy пользователем сохраняется. Для подтверждения нужен повторный запуск игры.

## Проверки

274 теста без ошибок и пропусков. Среди проверок: плавность на прежних границах
96×96, смешанный состав участков, детерминизм, точная voxel-геометрия берёзы,
crop-согласованность предпросмотра, момент создания API, отключённые coarse
mixin, сохранение неизвестных ключей настроек и поведение Chunky API при уже
запущенной задаче/неверном радиусе. Архивы сборки проверены отдельно.
Полный игровой прогон новой сборки, перезапуск Voxy и общий замер с C2ME/Chunky
не выполнены. Пользовательские JAR, конфиги, мир и LOD-кэш не заменялись.
